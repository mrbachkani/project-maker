# Project Rules

These rules apply to every project scaffold generated by the Project Maker.  They ensure consistency across templates and help both developers and AI tooling understand how to work within a project.

## Coding Conventions

- Use modern language versions (e.g. Node.js ≥ 16, Python ≥ 3.10).
- Use a linter and formatter (ESLint/Prettier for JavaScript, flake8/black for Python).
- Use environment variables for configuration; **never commit secrets** to the repository.
- Write unit tests for new features and run the test suite before committing.
- Follow the [Twelve‑Factor App](https://12factor.net/) principles where applicable.

## Directory Structure

- Place source code under `src/` (for web/mobile templates) or `services/` (for backend templates).
- Put tests under `tests/` mirroring the source structure.
- Keep configuration files in `config/` or at the root level (e.g. `.eslintrc.js`, `tsconfig.json`).
- Use the `components-library/` for reusable UI components so they can be shared across projects.

## Backend Integration

- Annotate components expecting data with a `// @fetch:<source>` comment followed by a hint about the backend source.
- Use the `scripts/bind-backend.js` script or the Windsurf `/bind-backend` workflow to automatically wire annotated components to your chosen backend.  The script understands JavaScript and TypeScript files and injects guidance for Firebase, Supabase, and REST APIs.
- Surface loading, error, and empty states in the UI so backend outages or slow calls do not break the experience.
- Keep secrets in a `.env` file which is never committed; include a `.env.example` with the keys needed.  Document required variables in the PRD and task breakdown templates.
- Maintain service modules (e.g. `services/api.ts`) that encapsulate data access; frontend components should depend on those modules instead of calling backends directly.

## Full-Stack Validation

- Every feature must ship with an end-to-end test plan that exercises the new UI against the real (or staged) backend.
- Before merging, run the `/full-stack-check` workflow or reproduce its steps manually: start backend services, seed required data, run the frontend, and execute smoke tests that cross the stack.
- Add health checks and logging for new endpoints so issues can be diagnosed quickly in production.

## Pull Requests

- Update documentation when you add features or change behaviour.
- Ensure the code builds and all tests pass.
- Follow the lint rules; fix lint errors before requesting review.
